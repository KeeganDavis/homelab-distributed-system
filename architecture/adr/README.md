# Architecture Decision Records

Use ADRs for meaningful architectural decisions involving alternatives and
tradeoffs.

Do not create ADRs for routine implementation details.

## Naming

`NNN-short-decision-name.md`

Example:

`001-use-jenkins-for-ci-cd.md`

## Template

# ADR NNN: Decision

## Status

Proposed | Accepted | Superseded

## Context

What problem or decision exists?

## Options Considered

- Option A
- Option B
- Option C

## Decision

What was selected?

## Rationale

Why?

## Tradeoffs

What benefits and disadvantages does the decision create?

## Consequences

What does this decision mean for future implementation?
